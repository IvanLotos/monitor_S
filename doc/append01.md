Приложение А. Проверка содержимого ответа (check_content)

Данное приложение является неотъемлемой частью документации и описывает функциональность поля check_content в конфигурации модуля http_check.

1. Назначение

Поле check_content позволяет выполнять проверку содержимого тела HTTP-ответа (response body) после того, как подтверждён ожидаемый HTTP-статус. Это необходимо для случаев, когда успешный статус (например, 200) ещё не гарантирует корректность ответа, и требуется убедиться, что в теле присутствует определённая строка, ключевое слово или шаблон.

2. Формат

В конфигурации модуля http_check для каждого endpoint может быть указан параметр check_content. Значение может быть двух типов:

· Обычная строка – выполняется проверка на прямое вхождение подстроки в тело ответа. Сравнение регистрозависимое.
· Регулярное выражение – если строка начинается с префикса re: (латинские буквы, двоеточие), то остальная часть интерпретируется как регулярное выражение (PCRE-совместимое) с флагом re.IGNORECASE (регистронезависимый поиск). Проверяется наличие хотя бы одного совпадения в теле ответа.

3. Правила обработки

1. Проверка выполняется только при успешном статусе.
      Если HTTP-статус ответа не совпадает с ожидаемым (expected_status), то проверка check_content не выполняется, и результат для данного endpoint считается False (неуспех).
2. Если check_content не указан – проверка содержимого пропускается, и результат определяется только по статусу.
3. Обычная строка – поиск подстроки выполняется с помощью оператора in в Python. Регистр имеет значение. Пример:
      check_content: "OK" – ответ должен содержать ровно подстроку "OK" (заглавные).
4. Регулярное выражение – для поиска используется функция re.search(pattern, response.text, re.IGNORECASE).
   · Шаблон должен быть валидным регулярным выражением.
   · В случае синтаксической ошибки в шаблоне, модуль логирует ошибку и считает проверку неуспешной (False).
   · Поиск выполняется по всему тексту ответа, включая переносы строк.
5. Порядок проверок – сначала статус, затем (если статус успешный) содержимое.

4. Примеры использования

Пример 1: Проверка наличия слова "OK"

```yaml
endpoints:
  - host: "service.example.com"
    port: 8080
    path: "/health"
    expected_status: 200
    check_content: "OK"
```

Результат True, если статус 200 и в теле ответа встречается подстрока "OK".

Пример 2: Поиск по регулярному выражению (любой из вариантов)

```yaml
check_content: "re:success|ok|done"
```

Найдёт любое из слов success, ok, done (регистр не важен).

Пример 3: Поиск JSON-значения

```yaml
check_content: "re:\"status\"\\s*:\\s*\"running\""
```

Найдёт фрагмент "status": "running" с любыми пробелами.

Пример 4: Игнорирование проверки при ошибке статуса

Если сервер вернул статус 500, проверка check_content не выполняется, результат – False.

5. Ограничения и рекомендации

· Производительность. Использование сложных регулярных выражений на больших телах ответов может замедлить выполнение модуля. Рекомендуется делать проверки по коротким строкам или простым шаблонам.
· Регистр. Для обычных строк регистр важен; используйте re: если требуется регистронезависимость.
· Экранирование. В YAML обратная косая черта \ является escape-символом, поэтому при написании регулярных выражений, содержащих \, необходимо экранировать их (удваивать). В примерах выше показано, как писать "re:\"status\"\\s*:" – это экранирование кавычек и косой черты.
· Ошибки в выражении. При невалидном регулярном выражении модуль запишет ошибку в лог и вернёт False. Рекомендуется тестировать выражения отдельно (например, в Python-интерактивном режиме) перед внесением в конфиг.

6. Отладка

Для проверки работы check_content рекомендуется установить уровень логирования full для соответствующего endpoint. Тогда в логах будет видно тело ответа (первые 1000 символов) и результат проверки содержимого. Это помогает убедиться, что шаблон написан корректно.

7. Будущие расширения

В следующих версиях модуля планируется добавить:

· Возможность проверки отсутствия подстроки (через префикс not: или аналоги).
· Поддержку проверки JSON-схемы.
· Возможность задавать несколько условий (AND/OR).

---

Приложение актуально для версии модуля http_check 1.0.0 и выше.
