## 1. Назначение

Модуль `local_listener_check` предназначен для централизованной проверки наличия TCP-портов, слушающих на локальном интерфейсе (127.0.0.1 и ::1) на удалённых хостах. Вместо прямого сканирования портов модуль опрашивает агент мониторинга (система АГЕНТ), который уже собрал эту информацию, и сравнивает полученный список с заданным перечнем портов.

**Основные задачи:**
- Получение актуального списка слушающих портов от агента по защищённому каналу (HTTPS + mTLS).
- Фильтрация портов, указанных в конфигурации.
- Формирование результата в виде булевых значений (присутствует/отсутствует) для каждого порта.
- Интеграция с ядром сервера S через стандартный контракт модулей.

**Область применения:**
- Мониторинг локальных сервисов, недоступных из сети (например, внутренние HTTP-серверы, базы данных, управляющие интерфейсы).
- Использование в панелях Grafana для отображения статусов критических портов.
- Автоматическое обнаружение отказов локальных компонентов.

## 2. Архитектура

Модуль реализован как отдельный Python-файл `local_listener_check.py` с конфигурационным файлом `local_listener_check.yaml`. Он следует контракту сервера S: предоставляет функцию `run(config) -> dict`.

**Внутренняя структура:**
- **Класс `LocalListenerChecker`** – основная логика.
- **Кастомный HTTPAdapter `MTLSAdapter`** – для настройки SSL-контекста с mTLS.
- **Метод `_check_single_host`** – опрос одного хоста, парсинг ответа, сравнение портов.
- **Метод `run`** – запуск параллельного опроса всех хостов с помощью `ThreadPoolExecutor`.

**Поток выполнения:**
1. При вызове `run` создаётся экземпляр `LocalListenerChecker` с переданным конфигом.
2. Для каждого хоста из списка `hosts` запускается задача в пуле потоков.
3. В задаче:
   - Определяется порт агента (глобальный или переопределённый для хоста).
   - Определяются пути к сертификатам (глобальные или переопределённые).
   - Выполняется HTTPS-запрос к `https://{host}:{agent_port}/v1/listeners`.
   - Ответ парсится, извлекается множество портов.
   - Для каждого проверяемого порта вычисляется наличие.
   - Возвращается словарь `{префикс.хост.порт: bool}`.
4. Все результаты объединяются и возвращаются в ядро.

## 3. Конфигурация

Конфигурационный файл `local_listener_check.yaml` содержит:

Параметр | Тип | Обязательный | Описание |
-- | -- | -- | -- |
 `prefix` | строка | нет (по умолчанию `listener`) | Префикс для ключей результата. |
 `cert_path` | строка | **да** | Путь к клиентскому сертификату (PEM). |
 `key_path` | строка | **да** | Путь к приватному ключу клиента. |
 `ca_chain_path` | строка | **да** | Путь к CA-цепочке для проверки сертификата агента. |
 `agent_port` | число | нет (по умолчанию 9500) | Глобальный порт агента. |
 `timeout` | число | нет (по умолчанию 5) | Таймаут HTTP-запроса в секундах. |
 `max_workers` | число | нет (по умолчанию 20) | Количество параллельных запросов. |
 `ports` | список чисел | **да (если не задано для хоста)** | Глобальный список проверяемых портов. |
 `hosts` | список объектов | **да** | Список хостов с возможностью переопределения параметров. |


Каждый элемент `hosts` может содержать:
- `host` (обязательно) – FQDN или IP-адрес.
- `agent_port` – переопределение порта агента для этого хоста.
- `ports` – переопределение списка портов.
- `cert_path`, `key_path`, `ca_chain_path` – переопределение путей к сертификатам.

**Пример конфигурации:**

```yaml
prefix: "listener"
cert_path: "/etc/ssl/default/client.crt"
key_path: "/etc/ssl/default/client.key"
ca_chain_path: "/etc/ssl/default/ca-chain.pem"
agent_port: 9500
timeout: 5
max_workers: 20
ports:
  - 22
  - 8080
hosts:
  - host: "web1.my.company.com"
  - host: "web2.my.company.com"
    agent_port: 9501
    ports:
      - 443
  - host: "web3.secure.company.com"
    cert_path: "/etc/ssl/host3/client.crt"
    key_path: "/etc/ssl/host3/client.key"
    ca_chain_path: "/etc/ssl/host3/ca-chain.pem"
```
## 4. Формат ответа агента и его обработка

Модуль ожидает от агента ответ в строгом контракте:
```json

{
  "module": "listeners",
  "version": "1.0.0",
  "success": true,
  "data": [
    {"state": "LISTEN", "local_address": "127.0.0.1", "port": 22, "raw": "..."},
    {"state": "LISTEN", "local_address": "::1", "port": 8080, "raw": "..."}
  ],
  "error": "",
  "duration_ms": 12.34,
  "metadata": {"count": 2}
}
```
Обработка:

    Проверяется HTTP-статус (должен быть 200).

    Проверяется поле success (должно быть true).

    Извлекается массив data, из каждого элемента берётся значение port.

    Формируется множество agent_ports.

    Для каждого порта из конфига проверяется вхождение в это множество.

Ошибки:

    Любая ошибка (таймаут, SSL, соединение, невалидный JSON, статус != 200, success=false) приводит к тому, что все порты для данного хоста считаются отсутствующими (False).

## 5. Примеры использования

Запрос к серверу S (после заполнения кэша):
```bash

curl http://localhost:8080/v3/listener
```
Ответ (фрагмент):
```json

[
  {"operation": "listener", "host": "web1", "value": true, "port": "22"},
  {"operation": "listener", "host": "web1", "value": false, "port": "8080"},
  {"operation": "listener", "host": "web2", "value": true, "port": "443"}
]
```
Фильтрация по группе:
```bash

curl http://localhost:8080/v3/listener/WEB
```
Вернёт только хосты, содержащие "WEB" в первом лейбле.

## 6. Требования и ограничения

Системные требования:

    Python 3.7+.

    Библиотека requests (устанавливается вместе с сервером S).

    Наличие клиентских сертификатов и CA-цепочки.

Сетевые требования:

    Хосты должны быть доступны по порту агента (обычно 9500) с сервера S.

    Используется HTTPS, порт должен быть открыт для входящих соединений.

Безопасность:

    Взаимная аутентификация по сертификатам (mTLS) обеспечивает защиту от несанкционированного доступа.

    Сертификаты должны быть подписаны доверенным УЦ.

Ограничения:

    Модуль не выполняет повторных попыток при ошибках – результат сразу становится False.

    Все ошибки логируются, но не влияют на работу других хостов.

    При горячей перезагрузке конфигурации модуль перечитывает свой YAML-файл, но код не перезагружается (изменения в логике требуют рестарта).

## 7. Устранение неполадок
Симптом	| Возможная причина |	Решение
-- | --
Все порты возвращают False	|Агент недоступен или возвращает ошибку	|Проверьте доступность хоста и порта агента с помощью curl с теми же сертификатами.
Ошибка SSL в логах	|Неверный сертификат, ключ или CA-цепочка	| Убедитесь, что файлы существуют и читаемы, проверьте цепочку сертификатов.
Таймауты	|Слишком маленький timeout или проблемы с сетью|	Увеличьте timeout, проверьте маршрутизацию.
Конфиг не применяется	|Синтаксическая ошибка в YAML|	Проверьте конфиг на валидность с помощью yamllint.
Модуль не загружается	|Нет файла .py или ошибка импорта|	Проверьте наличие файла, синтаксис Python, зависимости (requests).

## 8. Заключение

Модуль local_listener_check обеспечивает безопасный и эффективный способ мониторинга локальных портов через уже развёрнутых агентов. Его гибкая конфигурация позволяет адаптироваться к различным средам, а интеграция с сервером S даёт единую точку доступа к данным.
