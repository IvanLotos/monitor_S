# Руководство администратора сервера S

**Версия документации:** 2.2.0 
**Дата:** 2026-08-26 
**Соответствует версии сервера:** 2.1.0

---

## 1. Введение

Руководство предназначено для администраторов, устанавливающих, настраивающих и обслуживающих сервер S. Оно содержит инструкции по развёртыванию, конфигурированию, запуску, мониторингу и устранению типовых проблем.

**Требования к окружению:**
- Python 3.7 или выше (рекомендуется 3.8+).
- Библиотеки: `pyyaml`, `requests` (для HTTP-модуля и модуля local_listener_check).
- Рекомендуемая ОС: Linux (Ubuntu, CentOS, Debian).

**Функциональные особенности:**
- Все GET-запросы читают кэш и возвращают данные мгновенно.
- Фоновое обновление кэша выполняется с заданным интервалом.
- Эндпоинт `/refresh` позволяет принудительно обновить кэш.
- **Горячая перезагрузка конфигурации** без остановки сервера (подробнее см. раздел 4).
- **Возможность опроса удалённых агентов мониторинга через модуль local_listener_check** (см. раздел 5).

## 2. Установка

**Получение дистрибутива:** 
Скопируйте файлы сервера на целевую машину:
- `server.py` – основной скрипт.
- `config.yaml` – конфигурационный файл.
- Папка `modules/` с модулями и их конфигами.
- (Опционально) файл секретов `secrets.yaml` (разместить в защищённом месте).

**Установка зависимостей:**
```bash
pip install pyyaml requests   # requests – для http_check и local_listener_check
```
Создание структуры каталогов (рекомендуемая):
```bash

mkdir -p /opt/s/modules
mkdir -p /opt/s/logs
# Разместите server.py и config.yaml в /opt/s
```

## 3. Конфигурация

Файл config.yaml содержит все настройки сервера. Пример с пояснениями:
```yaml

host: "0.0.0.0"                 # IP-адрес для прослушивания
port: 8080                      # Порт
modules_dir: "./modules"        # Путь к папке с модулями

server:
  max_workers: 20               # Максимальное число одновременно обрабатываемых запросов

cache:
  refresh_interval: 60          # Интервал обновления кэша в секундах
config_watch_interval: 60       # -1 (отключено), 0 (только логирование, интервал 60с), >=60 (период проверки)

module_timeout: 30              # Максимальное время выполнения одного модуля (сек.)

logging:
  level: INFO                   # Уровень логирования: DEBUG, INFO, WARNING, ERROR, CRITICAL
  format: "%(asctime)s - %(name)s - %(levelname)s - %(message)s"
  datefmt: "%Y-%m-%d %H:%M:%S"
  file: "logs/server.log"       # Путь к файлу лога (если не указан, вывод в консоль)
  max_bytes: 10485760           # Размер файла до ротации (10 МБ)
  backup_count: 5               # Количество сохраняемых архивов
  module_levels:                # Переопределение уровня для отдельных модулей
    dns: DEBUG
```

Параметры можно изменять в любое время, но для применения изменений требуется перезапуск сервера (за исключением механизма горячей перезагрузки – см. раздел 4).

## 4. Автоматическое отслеживание изменений конфигурации (горячая перезагрузка)

Сервер поддерживает горячую перезагрузку конфигурационных файлов (основного config.yaml и всех модульных .yaml) без остановки сервера.

### Параметр **config_watch_interval**

Определяет режим работы:

· -1 – отслеживание отключено. Изменения конфигов требуют ручного перезапуска сервера.
· 0 – включён режим только логирования. Сервер проверяет файлы каждые 60 секунд и при обнаружении изменений записывает в лог сообщение с путём и временем изменения, но не перезагружает конфигурацию.
· >=60 – включён режим автоматической перезагрузки. Сервер проверяет файлы с заданным интервалом (в секундах). При обнаружении изменений выполняется перезагрузка GLOBAL_CONFIG и конфигов модулей (без перезагрузки кода модулей). Если интервал меньше 60, выводится предупреждение, но значение используется как есть.

### Что перезагружается?

· Обновляется содержимое GLOBAL_CONFIG (все параметры, кроме запрещённых).
· Обновляются конфиги каждого модуля (загружаются из соответствующих .yaml файлов).
· Кэш (CACHE) не трогается – он обновится по расписанию.
· Код модулей не перезагружается (только их конфиги).

### Запрещённые для горячей перезагрузки параметры

Следующие параметры не могут быть изменены через горячую перезагрузку и требуют ручного рестарта:

· host
· port
· server.max_workers
· cache.refresh_interval
· modules_dir
· config_watch_interval

При попытке их изменения в конфиге сервер залогирует ошибку и оставит старые значения.

### Обработка ошибок

· При синтаксической ошибке в YAML изменения не применяются, сервер продолжает работать со старой конфигурацией, ошибка логируется.
· Если модульный конфиг повреждён или отсутствует, перезагрузка отменяется, и сервер остаётся на старых конфигах (с логированием ошибки).

### Логирование событий

Типовые сообщения, связанные с работой вотчера:

· Config watcher started with interval 60s – запущен наблюдатель.
· Config file changed: config.yaml (mtime: ... -> ...) – обнаружено изменение файла.
· Configuration reloaded successfully – перезагрузка выполнена успешно.
· Forbidden configuration change detected: ... – попытка изменить запрещённый параметр.
· YAML parsing error in config file: ... – ошибка синтаксиса.

## 5. Управление модулями

· Добавление модуля: поместите файл модуля (имя_модуля.py) и его конфиг (имя_модуля.yaml) в папку modules/. При перезапуске сервера модуль будет автоматически загружен. При горячей перезагрузке конфигурации новые модули не добавляются (требуется ручной рестарт).
· Удаление модуля: удалите соответствующие файлы. Сервер не требует перезагрузки, но изменения вступят в силу только после перезапуска.
· Проверка загрузки: при старте в логах отображается список загруженных модулей с их версиями и путями к конфигам.

### Особенности модуля http_check:

· Для работы с авторизацией создайте отдельный файл секретов (например, /etc/s/secrets.yaml) с правами 600.
· В конфиге модуля http_check.yaml укажите путь к этому файлу через параметр secrets_file.
· В списке endpoints используйте auth_ref для ссылки на секрет.

### Особенности модуля local_listener_check:

· Модуль опрашивает удалённые агенты мониторинга по HTTPS с mTLS.
· Конфигурация модуля находится в modules/local_listener_check.yaml.
· Обязательные параметры: cert_path, key_path, ca_chain_path – пути к клиентскому сертификату, ключу и CA-цепочке для mTLS.
· Для каждого хоста можно переопределить порт агента (agent_port) и пути к сертификатам.
· Если агент недоступен или возвращает ошибку, все проверяемые порты для данного хоста считаются отсутствующими (False).
· Пример конфигурации приведён в разделе 11 (Приложение).

## 6. Запуск и остановка сервера

Ручной запуск:
```bash

cd /opt/s
python3 server.py
```
Запуск через systemd (рекомендуется):
Создайте файл /etc/systemd/system/s-server.service:
```ini

[Unit]
Description=S Server
After=network.target

[Service]
Type=simple
User=your_user
WorkingDirectory=/opt/s
ExecStart=/usr/bin/python3 /opt/s/server.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```
Затем выполните:
```bash

sudo systemctl daemon-reload
sudo systemctl enable s-server
sudo systemctl start s-server
```
Остановка: нажмите Ctrl+C при ручном запуске или выполните sudo systemctl stop s-server.

## 7. Логирование

Логи пишутся в файл, указанный в logging.file, или в консоль. Автоматическая ротация происходит при достижении max_bytes; старые файлы архивируются (server.log.1, server.log.2, …).

### Ключевые сообщения и их значение:

· Logging configured – логирование настроено.
· Loaded module: xxx (version x.x.x) – модуль успешно загружен.
· Cache updated successfully at ... – кэш обновлён.
· Module execution timed out after 30s – модуль превысил таймаут.
· Cache update timed out in background worker – фоновое обновление не уложилось в таймаут.
· Key '...' already exists, overwriting – конфликт ключей между модулями.
· Config watcher started with interval 60s – запущен наблюдатель за конфигами.
· Config file changed: config.yaml (mtime: ... -> ...) – обнаружено изменение файла.
· Configuration reloaded successfully – перезагрузка конфигурации выполнена успешно.
· Forbidden configuration change detected: ... – попытка изменить запрещённый параметр.
· (Для local_listener_check) Agent host:port returned status ... – предупреждение о нештатном ответе агента.
· (Для local_listener_check) SSL error for host:port – ошибка сертификата.

### Уровни логирования:

· DEBUG – детали выполнения модулей, полезна при отладке.
· INFO – обычные события (запросы, обновления кэша).
· WARNING – нештатные, но не критичные ситуации.
· ERROR – сбои модулей, таймауты, сетевые ошибки.

## 8. Тестирование работоспособности

### Базовые проверки с использованием curl:

· Проверка здоровья (любой эндпоинт):
bash

curl -s http://localhost:8080/ | jq

Ожидаемый ответ: JSON-массив (может быть пустым, если кэш ещё не заполнен).
· Получение данных в формате /v3 для операции portcheck:
bash

curl -s http://localhost:8080/v3/portcheck | jq

· Фильтрация по группам (например, PGL):
bash

curl -s http://localhost:8080/v3/portcheck/PGL | jq

· Принудительное обновление кэша:
bash

curl -X POST http://localhost:8080/refresh

Ответ: {"status":"ok","timestamp":"2026-08-17T12:00:00"}
· Проверка HTTP-модуля:
bash

curl -s http://localhost:8080/v3/http | jq

· Проверка модуля local_listener_check:
bash

curl -s http://localhost:8080/v3/listener | jq

## 9. Мониторинг и обслуживание

· Актуальность кэша: проверяйте время последнего обновления в логах или используйте модуль gettime, который возвращает completion_time в ответах.
· Очистка кэша: перезапуск сервера или вызов /refresh для перезаписи.
· Дисковое пространство: следите за размером лог-файлов; автоматическая ротация настроена.
· Мониторинг процессов: используйте systemd или внешний мониторинг для контроля состояния сервера.

## 10. Устранение неполадок
Проблема	| Возможное решение
-- | --
Модуль не загружается	| Проверьте наличие файла .py, функции run, синтаксис Python. Смотрите логи ошибок загрузки.
Ответ – пустой массив |	Кэш пуст – выполните /refresh вручную или дождитесь фонового обновления. Проверьте, что модули возвращают данные.
Таймауты или медленные ответы |	Увеличьте module_timeout или refresh_interval. Проверьте сетевую доступность целевых хостов.
Сервер не стартует	| Проверьте синтаксис config.yaml, доступность порта, права на каталог логов.
Ошибка SyntaxError: invalid syntax	| Используйте Python 3.7 или новее. Обновите Python или установите из PPA.
Предупреждения SSL	| Они подавлены в модуле http_check, но если появляются, добавьте urllib3.disable_warnings() в модуль.
Горячая перезагрузка не работает	| Убедитесь, что config_watch_interval задан корректно (не -1). Проверьте, что файлы имеют правильные права на чтение. Смотрите логи на наличие ошибок YAML.
Модуль local_listener_check возвращает все False	| Проверьте доступность агента по HTTPS с mTLS (curl с теми же сертификатами). Проверьте правильность путей к сертификатам и порта агента. Смотрите логи на наличие SSL-ошибок.
Ошибка SSL в local_listener_check	| Убедитесь, что клиентский сертификат и ключ корректны, CA-цепочка содержит корневой и промежуточный сертификаты. Проверьте, что сертификат агента подписан тем же CA.
